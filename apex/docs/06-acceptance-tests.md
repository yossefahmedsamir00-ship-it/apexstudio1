# 06 — اختبارات القبول

## تجربة الزائر

- فتح Home والخدمات والمشاريع من الكمبيوتر والموبايل.
- التحويل بين العربية والإنجليزية يعكس اتجاه الواجهة والنصوص.
- كل مشروع تجريبي يحمل وصفًا واضحًا بأنه Concept/Experimental.
- نموذج الطلب لا يرسل بيانات فارغة أو أطول من الحدود المعلنة.
- لا يظهر تأكيد نجاح إلا بعد نجاح عملية الحفظ.
- عند تعطّل Firestore تظهر رسالة فشل مفهومة مع الاحتفاظ بالبيانات داخل النموذج قدر الإمكان.

## صلاحيات Firestore

- زائر غير مسجل يستطيع قراءة مشروع منشور عام وخدمة منشورة عامة فقط.
- زائر غير مسجل لا يستطيع قراءة أو سرد مجموعة `requests`.
- زائر غير مسجل لا يستطيع تحديث أو حذف طلب موجود.
- طلب لا يحتوي كل الحقول المطلوبة يُرفض.
- `status` بقيمة غير `new` يُرفض للإنشاء العام.
- `createdAt` ليس server timestamp/request time فيُرفض.
- UID غير موجود في قائمة المسؤول لا يستطيع تعديل المشاريع أو الخدمات أو قراءة الطلبات.
- UID المسؤول يستطيع قراءة الطلبات وتعديل حالتها فقط بعد اعتماد القواعد واختبارها.

## لوحة الإدارة

- مستخدم غير مسؤول لا يصل إلى عمليات الإدارة حتى إذا فتح مسارها يدويًا.
- تحديث الحالة لا يغير بيانات الاتصال أو وصف الطلب بالخطأ.
- حذف/نشر مشروع يتطلب إجراءً صريحًا من المسؤول.
- عند انتهاء جلسة المصادقة، تُرفض عمليات الإدارة.

## الأداء والخصوصية

- الصور مضغوطة ومقاساتها مناسبة، ولا تُحمّل فيديوهات كبيرة تلقائيًا في أول شاشة.
- إعداد reduced motion محترم.
- لا يتم تحميل ملف عميل على رابط عام.
- لا يُخزّن نصوص المحادثات أو معلومات شخصية في analytics بلا حاجة وموافقة مناسبة.
- كل الروابط الخارجية تفتح سلوكًا واضحًا، مع عدم كشف مسارات المستودعات الخاصة.

## الاختبارات المطلوبة قبل الإنتاج

- Firebase Emulator Suite لقواعد Firestore.
- Browser checks لروابط/نماذج الواجهة.
- Build production.
- فحص الملفات المنشورة للتأكد من غياب الأسرار.
- اختبار يدوي على Android/iOS browsers وdesktop browsers المتاحة.
